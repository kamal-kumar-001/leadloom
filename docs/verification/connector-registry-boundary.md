# Connector registry transport and asynchronous probe boundary

The registry connector path and legacy DAG adapter path are separate implementations. Safeguards in one do not prove the other safe. This change closes the registry path's transport gaps before any production executor can depend on it.

All ten registry connectors use the shared bounded transport. It forces manual redirects, bounds the complete response body to1MiB, uses an abort signal and a10second default deadline capped at30seconds, and honors an explicit internal timeout option. The deadline covers headers and body reading. Declared and streamed oversized bodies are refused before connector JSON parsing. Redirect/error bodies are canceled without parsing or following them. The old json-only injected-fixture seam remains trusted internal test input; production global fetch must return a real response body.

A timeout/parse/network failure does not prove the provider did no work. Connector catch paths now mark these outcomes non-retryable; no automatic retry is added. Aborting a request does not recall a provider job or remove its possible charge. Explicit provider HTTP failures/rate limits retain their existing classifications; this is not an end-to-end idempotency guarantee. Vendor success JSON shape, price, credits and result meaning still require provider-specific validation and execution authority.

Remote base URL overrides must still match the vendor hostname and HTTPS, and now cannot contain credentials, query strings, fragments or alternate vendor ports. The local Ollama exception keeps its existing explicit loopback/port behavior, without allowing URL credentials/query/fragments. No request-supplied destination or transport is introduced.

Dropcontact's registry connector now matches the default-refusal posture of the legacy adapter: without an explicit injected fixture transport, it refuses before submitting any asynchronous request, even with the live flag enabled. TestConnectionService returns DISABLED before its own credential lookup; the HTTP route may still decrypt the already-selected saved key before invoking this service, but makes no provider request and does not change its verification state. This is not asynchronous execution or reconciliation. A future implementation must durably preserve the provider request/result and reconcile ambiguity before enabling submission.

The connection-test service additionally redacts the configured key in connector-returned error strings and thrown exceptions. Raw keys are not added to output, logs or archives. Stored-key presence and a connection-test result remain separate from an enrichment result, delivery verification, budget approval or product readiness.

Native route verification uses the real encrypted-vault repository and confirms unchanged saved credential/verification fields after a disabled Dropcontact test, zero external transport calls, and no decryption while the global live flag is off. Transport fixtures cover hung headers/body, cancellation, declared/streamed size limits, redirects, invalid timeout and base URLs, propagation through an actual connector, single-attempt behavior and key redaction. All provider replies are synthetic.
